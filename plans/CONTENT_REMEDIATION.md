# 网站内容整改方案（Content Remediation Plan）

> 背景：用户反馈"网站内容实在是太少了"。
> 经代码盘点，本项目功能骨架（三角色 RBAC、订单状态机、AI 店长/客服、推荐、优惠券等）已具备，
> **"内容少"的根因不是缺功能，而是：种子数据极度稀疏 + 首页内容模块空着 + 视觉物料廉价**。
> 本方案以主流电商（淘宝 / 京东 / 亚马逊 / 拼多多）首页结构与运营模块为对标，分 5 个阶段充实内容与页面。
>
> 复用既有分层（api / services / models / schemas）、事件总线 `events.py`、状态机 `state_machine.py`、审计 `audit_service`。
> 演示数据严格匿名（店铺/用户通用化，账号 demo 占位，绝不写真实姓名/学校等个人信息）。

---

## 一、现状诊断（为什么"看起来空"）

来自 `backend/app/core/seed.py` 与前端代码盘点：

| 维度 | 现状 | 问题 |
|---|---|---|
| 分类 | 仅 3 个一级分类，无子类 | 分类导航单薄，无法体现"品类丰富" |
| 商品 | 仅 **5 个**，全部属 1 个商家 | 集市/店铺/排行榜几乎无内容可展示 |
| 商家 | 仅 **1 个** merchant | "店铺街/品牌馆"概念不成立 |
| 评价 | 0 条 | 商品详情无评分、无口碑，信任感为零 |
| 促销/Banner | 无模型、无数据 | 首页"限时秒杀"等模块是空壳 |
| 优惠券 | 仅 2 张 seed | 领券中心无内容 |
| 销量字段 | 未填充 | 排序/排行榜无意义 |
| 商品图 | `placehold.co` 纯色占位 | 视觉廉价，像"没装修的毛坯房" |
| 通知/积分流水/收藏/订单 | 几乎为空 | 买家中心各页空白 |

**结论**：最快见效的整改 = 先做"数据充实"（P0），再做"首页内容模块 + 商品/店铺页重构"（P1–P2）。
功能侧已较完整，本方案尽量**复用现有接口**，仅在确需新数据时新增少量模型/接口。

---

## 二、对标分析（主流电商首页都在用什么模块）

综合淘宝 / 京东 / 亚马逊 / 拼多多首页结构，归纳出的"标配内容模块"：

1. **轮播 Banner / 运营位**（顶部大图轮播，可点跳转活动/分类）
2. **分类导航**（左侧或顶部，多级 hover 展开，覆盖全品类）
3. **限时秒杀 / 聚划算**（倒计时 + 低价爆款卡片）
4. **个性化推荐「猜你喜欢」**（信息流，本项目已有 `/recommendations`，需更多数据撑起）
5. **销量排行榜 / 好评榜**（榜单形态，强化"大家都在买"）
6. **领券中心 / 新人专区**（优惠券聚合领取）
7. **店铺街 / 品牌馆**（多商家露出，本项目 `GET /shops` 已可列出商家）
8. **主题频道入口**（数码 / 家居 / 文创等频道大图入口）
9. **商品详情页富内容**：多图画廊、规格参数、评分分布、评价列表（带图/筛选）、相关推荐、"看了又看"、店铺信息卡、问答
10. **买家个人中心**：资料、地址簿、积分成长、签到、消息中心、收藏夹、我的订单

---

## 三、整改目标与原则

- **目标**：让网站"第一眼像电商平台"——首页有内容、有推荐、有活动、有榜单；商品/店铺页信息饱满；买家中心各页非空。
- **原则**：
  - 数据先行（P0），用真实风格图（推荐 `picsum.photos/seed/<名>/600/400` 真实照片）替换纯色占位。
  - 复用现有接口；新增模型仅限"确实缺的数据"（Banner、Promotion、Address、ShopProfile 等）。
  - 每个阶段配套最小验证（seed 后可肉眼看效果 + `npm run build` + 关键 pytest）。

## 四、分阶段整改方案

### ★ P0 · 数据充实（最高性价比，立竿见影）

**目标**：把"毛坯房"填满——分类/商品/商家/评价/促销/优惠券/通知/积分 全部有量有质。

后端改动（`backend/app/core/seed.py`）：
1. **多级分类**：在现有 3 个一级分类下各挂 4–6 个二级子类（共 ~18 个），利用 `Category.parent_id` 建立父子关系（若模型暂无 `parent_id`，先加该字段，低成本）。
2. **多商家**：`DEMO_USERS` 增至 4–5 个 merchant（如 `merchant_a/b/c`，店铺名用通用品牌名如"云栖数码""原木生活馆"等匿名化名称）。
3. **海量商品**：`DEMO_PRODUCTS` 扩充到 **50–60 个**，覆盖各二级子类，分散到多个商家；填充 `sales`（销量）、`rating` 聚合所需字段，图片改用 `https://picsum.photos/seed/<商品名>/600/400`。
4. **评价**：每个热门商品挂 3–8 条评价（含 1–4 星分布、部分带图、部分含 AI 情感标签），让详情页评分分布/口碑真实。
5. **促销/秒杀数据**：新建 `Promotion` 模型（类型：秒杀/限时折扣/满减，含 `start_at/end_at/discount_price`），seed 3–5 场进行中活动。
6. **Banner 运营位**：新建 `Banner` 模型（标题/图/跳转类型/跳转 ID/排序），seed 3–4 张轮播。
7. **优惠券**：增至 6–10 张（平台券、各店铺券、新人券、折扣券），覆盖不同门槛/类型。
8. **买家侧数据**：为 `buyer` 预置收藏 3–5 件、通知 4–6 条、积分流水若干、1–2 条历史订单（含已评价）。

> ⚠️ 重置方式：删 `backend/ai_shop.db` 后双击启动即可重新 seed（脚本仅在库不存在时写入）。

---

### ★ P1 · 首页内容重构（对标京东/淘宝首页）

**目标**：Market.tsx 从"空壳模块"升级为"内容饱满的首页"。

前端改动（`frontend/src/pages/Market.tsx` + 新增组件）：
1. **轮播 Banner**：新增 `Carousel` 模块，消费 `GET /banners`，自动轮播、可点跳转。
2. **分类导航升级**：多级分类树（hover 展开二级），替代现有单级宫格。
3. **限时秒杀专区**：新增 `FlashSale` 模块，消费 `GET /promotions?type=flash`，带倒计时 + 低价卡片。
4. **排行榜**：新增「热销榜 / 好评榜」模块，按 `sales` / `rating` 取 Top 5–10。
5. **领券中心入口**：聚合展示可领优惠券，一键领取（接现有 `/coupons/{id}/claim`）。
6. **店铺街**：消费 `GET /shops`，露出多商家店铺卡，点进店铺页。
7. **主题频道**：数码/家居/文创大图入口，点击跳转对应分类筛选。
8. 保留并强化现有「猜你喜欢」「精选好物筛选」。

后端配套（仅补数据接口）：`GET /banners`、`GET /promotions`（秒杀/活动）、`GET /products?sort=top_sales|top_rating`。

---

### ★ P2 · 商品详情 & 店铺页充实

**目标**：点进商品/店铺不再是"一张图 + 一句话"。

商品详情 `ProductDetail.tsx`：
- 多图画廊（商品图数组，主图 + 缩略图切换）
- 规格参数表（新增 `Product.specs` JSON 字段：品牌/材质/尺寸等）
- 评分分布条（5→1 星占比）+ 评价列表（按"有图/好评/差评"筛选、分页）
- 相关推荐 / "看了又看"（同类目其他商品）
- 店铺信息卡（店名/评分/商品数，点击进店铺页）
- 问答区（可选，轻量）

店铺页 `Shop.tsx`（接现有 `GET /shops/{merchant_id}`）：
- 店招（店名 + 简介 + 优惠券）
- 店铺商品网格（按销量/最新排序）
- 店铺专属券领取

---

### ★ P3 · 买家个人中心内容

**目标**：买家登录后"有东西可看、有动作可做"。

新增/充实页面：
- **个人中心** `Me.tsx`：头像/资料编辑（`GET/PATCH /me`）、订单/收藏/积分快捷入口。
- **地址簿** `Address.tsx`：新增 `Address` 模型 + CRUD，结算时可选用。
- **积分成长中心** `Points.tsx`：等级进度条 + 积分流水（接现有 points）。
- **每日签到**：新增 `POST /me/signin`（每日一次、连签奖励），首页/个人中心放签到按钮。
- **消息中心** `Notifications.tsx`：列表 + 已读 + 红点（现有功能，确保有 seed 数据）。
- **收藏夹** `Favorites.tsx`：栅格卡片，一键加购（现有功能，确保有 seed 数据）。

---

### ★ P4 · 营销与数据内容（接 PLAN v3 的 A/B/C）

与既有路线图衔接，补齐"看起来像管理系统"的内容：
- **优惠券后台**（`CouponManager` 增强：商家/管理员创建/编辑/下发 UI，现有模型已支持）。
- **库存管理**：`StockLog` 流水 + 低库存预警（接事件总线通知商家）。
- **多维数据看板**：品类销售占比、用户增长、转化漏斗、客单价、时间范围选择（用 recharts 低成本补全视觉）。
- **积分商城**：积分兑换优惠券（接现有 coupon）。

## 五、优先级与实施顺序（推荐）

| 顺序 | 阶段 | 理由 | 估时 |
|---|---|---|---|
| 1 | **P0 数据充实** | 零前端风险，立刻让全站"有内容" | 短 |
| 2 | **P1 首页重构** | 用户第一眼感知最强 | 中 |
| 3 | **P2 商品/店铺页** | 提升转化与信任 | 中 |
| 4 | **P3 买家中心** | 留存与活跃 | 中 |
| 5 | **P4 营销/数据** | 平台"厚度"，可穿插 | 长 |

**建议首交成果**：P0 + P1（数据填满 + 首页六大模块），即可彻底改变"内容太少"的观感。

## 六、验收标准

- [ ] 首页含：轮播 Banner、多级分类、秒杀专区（倒计时）、排行榜、领券入口、店铺街、主题频道、猜你喜欢。
- [ ] 商品总数 ≥ 50，覆盖 ≥ 15 个二级分类、≥ 4 个商家；商品图为真实照片风格。
- [ ] 任意商品详情含：多图、规格、评分分布、≥ 3 条评价（含带图/差评）。
- [ ] 买家个人中心：资料/地址簿/积分/签到/消息/收藏 均有可见内容。
- [ ] 前端 `npm run build` 通过；关键链路（浏览→加购→下单→评价）肉眼走通。
- [ ] 演示数据零个人信息（店铺名/用户名通用化）。

---

## 七、复用与约束

- 写操作经 `audit_service.record()` 留痕；签到/领券/下单等事件经 `events.py` 总线解耦（通知、积分、审计）。
- 新增状态/流转一律进 `state_machine.py` 集中校验。
- 新增模型需同步：`models/`、`schemas/`、`api/`、并在 `seed.py` 提供演示数据；改动后跑 `pytest` 与 `npm run build`。
- 不破坏现有三角色权限；管理员/商家/买家视图各自充实，但不越权。
